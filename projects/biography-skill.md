# 个人传记 Skill：帮普通人写一本自己的传记

每个人都值得被记录，但传记写作对普通人来说门槛太高——不知道怎么开头、记不住具体时间、一写就变成流水账。这个 Agent Skill 把「写传记」变成一场自然的对话：AI 扮演专业传记访谈者，像聊天一样引导你回忆人生，自动把零散回忆整理成时间线，最后组织成连贯、有温度的章节成稿。

**GitHub 仓库**：[trumanzhongqiang/biography-skill](https://github.com/trumanzhongqiang/biography-skill) ｜ 当前版本 v1.2.0 ｜ MIT 开源

## 它是怎么工作的

```
聊天回忆 → 访谈式采集（问题库引导，保留原话）
        → 结构化整理（时间线 + 人物表 + 冲突确认）
        → 传记蓝图（章节划分，与你确认）
        → 章节化成稿（每章确认后定稿，支持无限续写）
```

- **访谈式采集**：像专业传记作者一样提问，一次只问一个问题，从细节切入而非问卷式盘问。「你童年快乐吗」不问，改问「小时候放学回家第一件事是做什么」
- **结构化整理**：素材实时落库成本地文件——时间线、人物表、待确认事项，前后说法冲突时主动找你确认，绝不自行编补
- **章节化成稿**：按八章结构组织素材，保留你自己的口头禅和情感色彩；每章 2000~4000 字，写完先给你看再定稿
- **照片与插图**：访谈中在合适时机自然引导你提供老照片；全程没有照片时，成稿后会询问是否配 AI 生成示意插图——明确标注「AI 生成示意图」，绝不冒充真实照片

## 关键设计决策

**为什么坚持「保留原话」？** 传记的第一读者是传主本人。把「我娘」润色成「我母亲」，传主就认不出这是自己说过的话，传记退化成流水线范文。所以 Skill 的红线里写明：对话和直接引语保留原话，润色只修病句、不动腔调。

**为什么矛盾要当场追问？** 新素材和旧记录冲突时沉默地记两个版本，雷会埋在定稿里——用户校稿时才发现自相矛盾，整章返工。所以冲突当场写入待确认清单，温和地问一句「你之前说 1985 年搬家，这次说的是 1987 年，哪个对」。

**为什么有「质检四查」？** 传记分次写成，单章都好、连起来失衡是常态。每章定稿前必须逐项通过：事实可溯（任抽一个硬事实能指回素材原文）、文风一致（遮住章节号任意两章连读无断裂感）、文字清晰（AI 套话出现一个删一个）、节奏（只读八段章首能讲清一生脉络）。任一查不过，不交付。

## 隐私与边界

所有素材保存在本地工作目录，不上传任何远程服务，敏感内容由用户自己决定保留还是删除。敏感话题（离别、创伤、家庭矛盾）不主动深挖；用户愿意讲就安静听完，记录时不渲染、不评价，去留由用户决定。

# 我的私房菜 Skill：帮每个家庭设计自己的菜单

「今天吃什么」是每天都在发生的难题。这个 Agent Skill 不推荐网红菜谱，而是帮每个家庭沉淀出属于自己的私房菜单——越用越懂你家的胃。

**GitHub 仓库**：[trumanzhongqiang/home-menu-skill](https://github.com/trumanzhongqiang/home-menu-skill) ｜ 当前版本 v1.1.1 ｜ MIT 开源

## 它是怎么工作的

```
聊出家庭画像（口味/忌口/设备/厨艺）
    → 按周排菜单（工作日快手菜 / 周末大餐，连续性感知不撞车）
    → 一键出采购清单（合并同类、扣减库存、双向对账）
    → 饭后反馈沉淀（太咸就校准，爱吃就进招牌菜）
```

- **家庭画像**：记录每个成员的口味偏好、忌口、过敏源、烹饪设备与厨艺水平，作为一切推荐的地基
- **菜单设计**：按周生成家常菜单，工作日快手菜、周末大餐自动区分；每道菜附一句理由，让主厨能判断而不是盲从
- **食材规划**：自动生成采购清单，合并同类食材、扣减家中库存，每个食材标注「用于哪天的哪道菜」
- **持续进化**：吃完反馈「太咸 / 孩子不爱吃 / 下次还想吃」，口味校准当场沉淀，下周菜单直接体现变化

## 关键设计决策

**为什么过敏是「零冲突」红线？** 「少量应该没事」的侥幸，代价是主厨的信任当场归零，严重时有人进医院。所以过敏源和忌口零冲突，宁可这周单调也不碰；拿不准的食材（如含小麦的成品酱料）标注存疑、主动询问，不默认安全。

**为什么清单要「双向对账」？** 菜单写了清蒸鲈鱼、清单里没有鱼，主厨在超市当场抓瞎。所以清单里每个食材要能指回某道菜，菜单里每个要买的食材必须进清单——对不上就回炉重排，不两头各写各的。

**为什么反馈必须落盘？** 嘴上说「好的下次注意」却什么都不记，同一道菜下次照样太咸，用户会觉得「说了也白说」。所以每条反馈必写进本地记录和画像字段，并当场告诉你「下次菜单哪里会变」。

## 隐私与边界

家庭画像、菜单、反馈全部保存在本地工作目录，不上传任何云服务。Skill 做口味和食材层面的规避（如少糖少油），但不做营养诊断、不谈「疗效」——特殊健康需求建议咨询医生或营养师。
